# hece_note 결정 사항

내 기기 5대(데스크톱, 노트북, 갤럭시 S26, 폴드8, 갤럭시탭 S9+)에서만 쓰는 개인 앱.
기능은 블로그용 스케줄표, 가계부, 냉장고 물품메모 세 가지이고, 블로그용 스케줄표부터 만든다.

## 확정한 것

### 1. 앱 형태: PWA + TypeScript

앱은 GitHub Pages에 올린 웹앱이다. 기기마다 브라우저에서 "홈 화면에 추가"(PC는 "앱 설치")로 한 번만 설치한다.
그 뒤로는 일반 앱처럼 아이콘을 눌러 연다.

업데이트는 이렇게 돌아간다. 코드를 `main`에 푸시하면 GitHub Actions가 빌드해서 Pages에 올린다.
앱을 켜면 서비스 워커가 새 버전이 있는지 확인하고, 있으면 받아서 바로 새 버전으로 다시 띄운다.
재설치나 설치 확인 창은 없다.

APK 방식을 버린 이유: 플레이스토어를 거치지 않은 APK는 업데이트할 때마다 안드로이드가 설치 확인을 띄운다.
"켤 때 무조건 최신"이라는 요구를 기기 5대에서 똑같이 만족하는 건 PWA뿐이다.

Python은 화면 코드에 쓰지 않는다. 백업·데이터 이전 같은 로컬 스크립트에만 쓴다.

화면 위쪽에 `v0.2.0` 꼴로 버전이 뜬다. 어느 버전이 떠 있는지 보고 업데이트가 됐는지 확인한다.
원본은 `package.json`의 `version`이고, **푸시하기 전에 올린다.** 기능을 더하면 가운데 숫자(0.2.0 → 0.3.0), 고치기만 하면 끝 숫자(0.2.0 → 0.2.1)를 올린다. 앞 숫자는 사용자가 정할 때만 올린다(냉장고 탭 추가로 1.0.0).
버전을 안 올리고 푸시하면 업데이트가 됐는지 화면으로 알 수 없다.

### 2. 백엔드: Supabase 무료 플랜

DB는 Postgres 하나다. 가계부와 냉장고는 일반 테이블로, 블로그 스케줄표는 JSONB 컬럼으로 담는다.
표와 JSON을 DB 하나로 해결한다.

- 무료 용량 500MB. 이미지가 없으니 충분하다.
- Realtime 기능으로 다른 기기에서 고친 내용이 새로고침 없이 바로 반영된다. 새로고침 버튼도 함께 둔다.
- **주의**: 무료 프로젝트는 7일 동안 요청이 없으면 일시정지된다. GitHub Actions로 며칠에 한 번 가벼운 요청을 보내서 막는다.

### 3. 로그인: 기기마다 한 번 입력하는 개인 키

Supabase에 사용자 계정을 딱 하나 직접 만들고, 가입 기능은 꺼 둔다.
그 계정의 비밀번호가 곧 "나만 아는 키"다. 로그인 ID는 앱에 고정해 두고 화면에서는 키만 묻는다.

앱을 처음 열면 키 입력 창이 한 번 뜬다. 맞으면 세션이 기기에 저장되고 그 뒤로는 묻지 않는다.
DB의 모든 테이블에는 RLS 규칙을 걸어 이 계정만 읽고 쓰게 한다.

저장소와 사이트는 공개 상태다. 그래서 코드와 Supabase 주소·공개 키는 누구나 볼 수 있다.
그래도 키 없이는 데이터를 한 줄도 못 읽는다. 키는 20자 이상으로 길게 정한다.

## 확정한 것: 블로그 스케줄 달력

### 화면 톤
- 밝은 톤이다. 바탕은 연한 회색(`#f1f5f9`), 패널과 입력칸은 흰색, 글자는 짙은 남색(`#0f172a`)이고 강조색은 파랑(`#2563eb`)이다. 색은 모두 `src/style.css` 맨 위의 토큰에서 바꾼다.
- 가독성 기준: 달력 칸 안의 글자(분야·주제·날짜·담당·다음 단계)는 칸 색과 대비 7:1 이상, 나머지 글자는 4.5:1 이상이다. 새 색을 더하면 이 기준으로 다시 잰다.
- 못 누르는 것(잠긴 체크 항목, 비활성 버튼·입력칸)은 투명도로 흐리게 하지 않는다. 글자는 또렷하게 두고 점선 테두리와 회색 바탕으로 구분한다.
- 달력 칸 색: 하늘색·분홍은 그대로이고, 분야만 있는 칸은 흰색(연한 회색 테두리), 예약 칸은 연한 회색(`#cbd5e1`)이다. 오늘은 주황 테두리, 선택한 칸은 파랑 테두리다.
- 앱 아이콘과 상태 표시줄 색도 밝은 톤이다(파랑 바탕에 흰 문서). 이미 설치한 앱은 아이콘이 바로 안 바뀔 수 있고, 다시 설치하면 바뀐다.

### 탭
- 화면 맨 아래 줄의 왼쪽에 탭이 있고, 오른쪽 끝에 버전이 있다. 지금은 "블로그"와 "냉장고" 탭이 있다.
- 가계부를 만들면 탭이 늘어난다. 기능 목록은 `src/tabs.ts`의 `FEATURES`이고, 탭을 더할 때는 여기에 **한 항목**(id, 이름, 화면, 시작·정리 함수, 연결 상태)만 추가하면 된다. `App.svelte`는 고치지 않는다.
- 폴더 규칙: 기능마다 `src/features/<이름>/`에 화면·규칙·데이터를 모은다. 알림(토스트), 날짜 계산, 쓰기 줄 세우기, 화면 크기처럼 기능이 함께 쓰는 것은 `src/core/`에 둔다. 새 테이블은 `supabase/migrations/`에 다음 번호의 새 파일로 만든다.
- 모든 기능 화면은 로그인 직후부터 함께 올라가 있고, 현재 탭이 아닌 화면은 숨기기만 한다. 그래서 탭을 오가도 보던 달과 선택한 날짜가 남는다.
- 로그아웃 버튼은 각 탭 화면의 위쪽 줄 오른쪽 끝에 둔다(블로그는 새로고침 옆). 누르면 `src/core/session.svelte.ts`로 요청하고 `App.svelte`가 모든 기능을 정리한다. 새 탭도 같은 방식으로 버튼을 둔다. 세션이 만료되거나 다른 곳에서 로그아웃돼도 로그인 화면으로 돌아간다.
- 맨 아래 줄의 "실시간/끊김"은 지금 보는 탭의 연결 상태다.
- "오늘"은 `src/core/clock.svelte.ts`가 화면이 다시 보일 때와 1분마다 확인해, 자정이 지나면 오늘 표시가 따라간다.
- 접근성: 날짜 칸은 날짜·분야·담당·주제·다음 단계를 말로 읽어 준다. 모달은 열리면 포커스가 안으로 들어가고, Esc로 닫으며, 닫으면 눌렀던 칸으로 돌아간다. 탭은 탭 화면과 연결돼 있다.
- 마지막으로 보던 탭은 기기에 기억한다. 기억해 둔 탭이 없어졌으면 기본 탭(블로그)으로 열린다.
- 탭 화면은 하단 줄 위까지만 차지한다. 앱 전체 스크롤이 없다는 규칙은 모든 탭에 같다.

### 화면
- 달력이 메인이고 항상 켜져 있다. 블로그는 하나다.
- 태블릿형: 좌측 달력, 우측 아이템 항목. 모바일형: 화면 중앙에 달력, 날짜를 누르면 모달로 아이템을 보여준다.
- 두 형태는 화면 폭으로 나눈다. 폴드8은 접으면 모바일형, 펼치면 태블릿형이다.
- 달력 칸에는 분야와 주제만 글자로 보인다. 나머지는 눌러야 보인다.
- 분야·주제 글자 크기는 절대값이 아니라 **칸의 가로·세로를 재서** 정한다(`src/features/blog/cell-font.ts`). 기본은 칸 안쪽 폭의 1/6(한글 6글자가 한 줄)이다.
  폰처럼 칸이 홀쭉해서 기본값이 8px보다 작아지면, 칸이 허락하는 만큼(한 줄 4글자 이상, 세로 4줄 이상) 키워서 8px를 지킨다. 이미 8px 이상인 칸(폴드 안쪽, 태블릿)은 기본값 그대로다. 위쪽 한도는 24px.
  화면 크기가 바뀌거나 주 수(4~6줄)가 바뀌면 다시 잰다.

### 하루 아이템
날짜 하나에 아이템 하나다. 필드는 이 순서다.

1. 분야: 레시피,제품 / 뷰티 / 맛집,여행
2. 담당: 행이 / 챙이
3. 주제: 문자열
4. 사진촬영, 글작성, 글보정, 연관글, 예약: 모두 bool, 기본값 false

**잠금**: 앞 필드가 채워지지(true가 되지) 않으면 뒤 항목은 체크할 수 없다.
앞 항목을 해제하려는데 뒤에 true가 있으면 **해제 자체를 막는다.** 뒤 항목을 먼저 풀어야 한다.

### 분야 기본값
- 11월 8일을 "레시피,제품"으로 두고 3개가 하루씩 번갈아 돈다. 8일 이전 날짜도 같은 순서로 거슬러 계산한다.
- 날짜별로 수동으로 바꿀 수 있고, 바꾼 값은 그 날짜에만 남는다. 이후 날짜를 다시 계산하지 않는다.
- 기본 순환 규칙을 나중에 바꿔도 **지난 날짜는 그대로**다. "이 날짜부터 새 규칙"으로 이력을 남긴다. 설정 화면은 만들지 않는다.

### 칸 색
칸은 항상 단일색이다. 겹치는 색은 없다. 아래 순서로 먼저 맞는 것을 쓴다.

1. 예약 true → 회색 (회색은 예약 전용이다)
2. 글보정 true → 하늘색 (Blue)
3. 글작성 true → 분홍 (Pink)
4. 담당이 있으면 행이는 하늘색 (B), 챙이는 분홍 (P). 주제가 있는지, 사진을 체크했는지는 색을 바꾸지 않는다.
5. 분야만 있고 담당이 없으면 흰색
6. 연관글은 색에 영향이 없다.

색만으로 구분이 어려우니 칸 색에 맞춰 글자를 작게 붙인다. 하늘색 칸은 "행이", 분홍 칸은 "챙이"다. 담당이 아니라 **지금 칸 색**을 따르므로, 글작성(분홍)·글보정(하늘색) 단계에서는 담당과 다른 글자가 붙을 수 있다. 회색·흰색 칸에는 붙이지 않는다.

### 칸 하단의 다음 단계
- 시작한 날짜(담당·주제·체크 중 하나라도 있는 날짜)의 칸 맨 아래에 **다음에 해야 할 단계**가 `사진촬영`처럼 뜬다.
- 순서는 담당 → 주제 → 사진촬영 → 글작성 → 글보정 → 연관글 → 예약이고, 아직 안 한 첫 단계를 보여 준다. 이름은 줄이지 않고 항목 패널과 같은 원문(담당, 주제, 사진촬영, 글작성, 글보정, 연관글, 예약)을 쓴다. 칸이 좁아서 표시 글자 크기를 칸 폭에 맞춘다.
- 분야만 있는 날짜와 예약까지 끝난 날짜에는 표시하지 않는다.
- 어떤 칸 색(하늘색·분홍·흰색·회색) 위에서도 눈에 띄도록 어두운 바탕에 밝은 노랑 글자로 그린다.

### 달 넘기기
- 달력을 좌우로 크게 쓸면 달이 넘어간다. 왼쪽으로 쓸면 다음 달, 오른쪽으로 쓸면 이전 달이다. 달력 폭의 1/4(최소 80px) 이상 옆으로 밀어야 하고, 위아래로 밀린 것보다 1.5배 이상 옆으로 가야 한다.
- 터치는 길게 누르지 않고 바로 밀면 쓸어 넘기기이고, 길게 누른 뒤 끌면 아이템 이동이다. 마우스로 내용 있는 칸을 잡으면 아이템 이동이고, 빈 칸에서 밀면 쓸어 넘기기다.
- 이전/다음 달 버튼과 오늘 버튼은 그대로 쓸 수 있다.

### 날짜 이동 (드래그 앤 드롭)
- 아이템은 다른 날짜로 끌어서 옮긴다. 터치는 길게 눌러 끌기로 하고, 모달에도 날짜 이동 버튼을 둔다.
- **분야도 아이템과 함께 따라간다.** 도착 날짜의 분야가 옮긴 아이템의 분야로 바뀐다.
- 떠난 날짜는 담당·주제·체크가 초기화되고, **분야는 옮겼던 값 그대로 남는다.**
- 도착 날짜에 주제가 있으면 이동을 막는다. 담당까지만 있으면 덮어쓴다.

### 저장과 기술
- 날짜별 분야는 모두 저장한다. 순환 규칙은 빈 날짜를 처음 열 때 분야를 채우는 데만 쓴다. 이동으로 분야가 복제되기 때문이다.
- 순환 규칙은 `blog_category_rules`에 이력으로 둔다(`effective_from`, 기준일, 순서). 스키마는 `supabase/migrations/0002_blog.sql`.
- 화면은 먼저 바꾸고 서버에는 나중에 보낸다. 서버에 쓰는 일은 한 줄로 세워 **누른 순서대로** 보낸다(`src/core/write-queue.ts`).
  쓰는 동안 들어온 실시간 알림과 다시 불러오기는 무시하고, 다 끝나면 한 번만 다시 불러온다.
  이렇게 하지 않으면 연달아 누른 값이 서버에서 뒤집히거나, 돌아온 알림이 방금 바꾼 화면을 옛 값으로 덮는다.
- 날짜 이동은 두 행을 한 번에 바꿔야 해서 `move_blog_day(from, to)` 함수로 처리한다.
- 날짜를 기본키로 한 행 하나에 아이템 하나를 둔다. 필드는 JSONB가 아니라 일반 컬럼이다. 항목이 늘면 컬럼을 추가한다.
- RLS와 Realtime은 기존 접속 기록 테이블과 같은 방식이다.
- 화면 프레임워크는 Svelte(Vite)다.
- 알림과 오프라인 쓰기는 이번 범위에서 뺀다. 달력이 돌아간 뒤 필요하면 붙인다.

## 확정한 것: 냉장고

### 화면
- 메인은 위(냉장고)·아래(냉동고) 두 구역이 높이를 반씩 나누고, 각 구역은 좌우 두 칸이다. 냉장고는 신선/양념, 냉동고는 재료/밀키트.
- 칸을 누르면 블로그 아이템 화면처럼 열린다. 넓은 화면은 오른쪽 패널(처음엔 냉장고·신선), 좁은 화면은 모달이다. 모달 공통 동작은 `src/ui/Modal.svelte`.
- 메인의 칸에는 오래된 재료부터 칸 높이가 허락하는 줄 수만큼 보인다(줄 높이 20px로 센다). 넘치면 마지막 줄이 "+N개"가 된다.
- 위쪽 줄의 월 변경 자리에는 "구매목록" 버튼이 있다. 체크 안 한 항목 수가 배지로 붙는다.

### 재료
- 필드는 이름(40자까지), 추가된 날짜(시간 없이 날짜만, 기본 오늘, 고칠 수 있음), 개수(선택, 단위 없음)다. 이름이 같은 재료도 따로 둔다. 이미 넣은 재료의 날짜도 칸 화면에서 날짜 글자를 눌러 달력으로 바꿀 수 있고, 바꾸면 정렬 순서도 따라간다.
- 날짜는 연도까지 쓰고(칸 화면 `2026-11-08`, 메인 `26/11/8`), 오늘까지 지난 날수를 `5일`·`오늘`로 함께 보여준다. 메인 칸은 좁으면 지난 날수만, 칸 폭이 190px 이상이면 날짜도 보인다.
- 칸 화면의 추가 입력(이름·날짜·개수·추가 버튼)은 한 줄이고, 입력 세 칸은 폭이 같다. 목록의 재료도 한 줄(이름 · 날짜와 지난 날수 · 개수 · 삭제)이다.
- **개수 없음도 정상 재료다.** 비활성이 아니다. 개수는 1 이상 999 이하의 정수만 받는다.
- 늘리기: 개수 없음 → 1, 이후 +1. 줄이기: 1에서 줄이면 개수 없음으로 돌아가고, 개수 없음에서는 줄이기 버튼이 눌리지 않는다. 입력칸에 직접 쓰거나 비워도 된다.
- 정렬은 추가된 날짜가 오래된 순이다. 날짜가 같으면 먼저 넣은 재료가 앞이다. 메인과 칸 화면이 같은 기준이다.
- 삭제는 확인 없이 바로 지운다. 재료 이름 수정은 만들지 않았다(지우고 다시 넣는다).

### 구매목록
- 모달 하나. 맨 위 입력 한 줄 + 엔터로 추가하고, 항목은 두 열로 촘촘히 놓는다. 눌러서 체크하면 아래로 내려가고, 줄마다 ✕로 지운다. 체크한 항목은 위쪽의 "체크 N개 삭제" 한 번으로 지운다.
- DB에 저장하고 실시간으로 기기끼리 같이 본다.

### 저장과 기술
- 테이블은 `fridge_items`, `shopping_items`(`supabase/migrations/0003_fridge.sql`). id와 생성 시각은 앱이 만들어 보낸다(화면을 먼저 바꾸기 때문).
- 칸 이름은 DB에 `fridge_fresh`·`fridge_sauce`·`freezer_ingredient`·`freezer_mealkit`로 저장한다. 규칙은 `src/features/fridge/domain.ts`, 스키마와의 일치는 `tests/unit/schema-parity.test.ts`가 확인한다.
- 쓰기와 실시간 처리 방식은 블로그와 같다(`WriteQueue`).
