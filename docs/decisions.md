# hece_note 결정 사항

내 기기 5대(데스크톱, 노트북, 갤럭시 S26, 폴드8, 갤럭시탭 S9+)에서만 쓰는 개인 앱.
기능은 블로그용 스케줄표, 가계부, 냉장고 물품메모 세 가지이고, 블로그용 스케줄표부터 만든다.

## 확정한 것

### 1. 앱 형태: PWA + TypeScript

앱은 GitHub Pages에 올린 웹앱이다. 기기마다 브라우저에서 "홈 화면에 추가"(PC는 "앱 설치")로 한 번만 설치한다.
그 뒤로는 일반 앱처럼 아이콘을 눌러 연다.

업데이트는 이렇게 돌아간다. 코드를 `main`에 푸시하면 GitHub Actions가 빌드해서 Pages에 올린다.
앱을 켜면 서비스 워커가 새 버전이 있는지 확인하고, 있으면 받아서 바로 새 버전으로 다시 띄운다.
재설치나 설치 확인 창은 없다.

APK 방식을 버린 이유: 플레이스토어를 거치지 않은 APK는 업데이트할 때마다 안드로이드가 설치 확인을 띄운다.
"켤 때 무조건 최신"이라는 요구를 기기 5대에서 똑같이 만족하는 건 PWA뿐이다.

예외: 가계부의 문자 불러오기는 웹앱이 문자함을 읽을 수 없어서 폰에만 안드로이드 앱(APK)을 따로 설치한다. 이 APK는 화면을 품지 않고 위 배포 주소를 열기만 하는 껍데기라서, 화면 업데이트는 지금처럼 배포만 하면 되고 APK는 다시 설치하지 않는다. 문자 읽기 같은 폰 쪽 기능을 바꿀 때만 새 APK를 설치한다. 나머지 기기는 그대로 PWA다. 계획은 [docs/ledger-plan.md](ledger-plan.md).

Python은 화면 코드에 쓰지 않는다. 백업·데이터 이전 같은 로컬 스크립트에만 쓴다.

화면 위쪽에 `v0.2.0` 꼴로 버전이 뜬다. 어느 버전이 떠 있는지 보고 업데이트가 됐는지 확인한다.
원본은 `package.json`의 `version`이고, **푸시하기 전에 올린다.** 기능을 더하면 가운데 숫자(0.2.0 → 0.3.0), 고치기만 하면 끝 숫자(0.2.0 → 0.2.1)를 올린다. 앞 숫자는 사용자가 정할 때만 올린다(냉장고 탭 추가로 1.0.0).
버전을 안 올리고 푸시하면 업데이트가 됐는지 화면으로 알 수 없다.

### 2. 백엔드: Supabase 무료 플랜

DB는 Postgres 하나다. 가계부와 냉장고는 일반 테이블로, 블로그 스케줄표는 JSONB 컬럼으로 담는다.
표와 JSON을 DB 하나로 해결한다.

- 무료 용량 500MB. 이미지가 없으니 충분하다.
- Realtime 기능으로 다른 기기에서 고친 내용이 새로고침 없이 바로 반영된다. 새로고침 버튼도 함께 둔다.
- **주의**: 무료 프로젝트는 7일 동안 요청이 없으면 일시정지된다. GitHub Actions로 며칠에 한 번 가벼운 요청을 보내서 막는다. 또 GitHub은 공개 저장소에 60일 동안 커밋이 없으면 예약 실행을 꺼 버리므로, 같은 워크플로가 마지막 커밋이 45일 넘게 지났을 때 빈 커밋(`[skip ci]`)을 하나 남긴다.

### 3. 로그인: 기기마다 한 번 입력하는 개인 키

Supabase에 사용자 계정을 딱 하나 직접 만들고, 가입 기능은 꺼 둔다.
그 계정의 비밀번호가 곧 "나만 아는 키"다. 로그인 ID는 앱에 고정해 두고 화면에서는 키만 묻는다.

앱을 처음 열면 키 입력 창이 한 번 뜬다. 맞으면 세션이 기기에 저장되고 그 뒤로는 묻지 않는다.
DB의 모든 테이블에는 RLS 규칙을 걸어 이 계정만 읽고 쓰게 한다.

저장소와 사이트는 공개 상태다. 그래서 코드와 Supabase 주소·공개 키는 누구나 볼 수 있다.
그래도 키 없이는 데이터를 한 줄도 못 읽는다. 키는 20자 이상으로 길게 정한다.

### 4. 인터넷이 끊기면 앱을 막는다
- 인터넷이 끊기면 **앱 전체를 비활성(`inert`)으로 하고 "인터넷에 연결되지 않았다" 창을 덮는다**(`src/ui/Offline.svelte`). 로그인 화면을 포함한 모든 화면이 대상이다. 오프라인에서 쓴 내용이 서버에 저장되지 못하는 일을 막으려는 것이다. 다시 이어지면 저절로 닫히고, "다시 확인" 버튼도 있다.
- 브라우저의 online/offline 알림만으로는 "와이파이는 붙었는데 인터넷이 안 되는" 경우를 알 수 없어서, **서버 주소에 실제로 닿는지 가볍게 확인**한다(`src/core/connection.svelte.ts`, 응답 내용은 읽지 않는 HEAD 요청). 끊긴 동안 3초마다, 이어진 동안 30초마다, 그리고 online 알림·화면이 다시 보일 때 확인한다. offline 알림은 확인을 기다리지 않고 바로 창을 띄운다.
- 다시 이어지면 각 기능의 실시간 연결이 다시 붙으면서 그사이 바뀐 내용을 가져온다.

## 확정한 것: 블로그 스케줄 달력

### 화면 톤
- 밝은 톤이다. 바탕은 연한 회색(`#f1f5f9`), 패널과 입력칸은 흰색, 글자는 짙은 남색(`#0f172a`)이고 강조색은 파랑(`#2563eb`)이다. 색은 모두 `src/style.css` 맨 위의 토큰에서 바꾼다.
- 가독성 기준: 달력 칸 안의 글자(분야·주제·날짜·담당·다음 단계)는 칸 색과 대비 7:1 이상, 나머지 글자는 4.5:1 이상이다. 새 색을 더하면 이 기준으로 다시 잰다.
- 못 누르는 것(잠긴 체크 항목, 비활성 버튼·입력칸)은 투명도로 흐리게 하지 않는다. 글자는 또렷하게 두고 점선 테두리와 회색 바탕으로 구분한다.
- 달력 칸 색: 하늘색·분홍은 그대로이고, 분야만 있는 칸은 흰색(연한 회색 테두리), 예약 칸은 연한 회색(`#cbd5e1`)이다. 오늘은 주황 테두리, 선택한 칸은 파랑 테두리다.
- 앱 아이콘과 상태 표시줄 색도 밝은 톤이다(파랑 바탕에 흰 문서). 이미 설치한 앱은 아이콘이 바로 안 바뀔 수 있고, 다시 설치하면 바뀐다.

### 탭
- 화면 맨 아래 줄의 왼쪽에 탭이 있고, 오른쪽 끝에 버전이 있다. 지금은 "블로그"·"냉장고"·"가계부" 탭이 있다.
- 탭을 늘릴 때는 기능 목록만 고친다. 기능 목록은 `src/tabs.ts`의 `FEATURES`이고, 탭을 더할 때는 여기에 **한 항목**(id, 이름, 화면, 시작·정리 함수, 연결 상태)만 추가하면 된다. `App.svelte`는 고치지 않는다.
- 폴더 규칙: 기능마다 `src/features/<이름>/`에 화면·규칙·데이터를 모은다. 알림(토스트), 날짜 계산, 쓰기 줄 세우기, 화면 크기처럼 기능이 함께 쓰는 것은 `src/core/`에 둔다. 새 테이블은 `supabase/migrations/`에 다음 번호의 새 파일로 만든다.
- 서버와 맞춰 쓰는 기능의 스토어는 `src/core/synced-store.svelte.ts`의 `SyncedStore`를 상속한다. 불러오기(오래된 응답 버리기), 쓰기 줄 세우기, 쓰는 동안 실시간 알림 미루기, 로그아웃 뒤 재조회 막기가 여기 한 곳에 있다. 새 탭의 스토어는 무엇을 불러오고(`fetchSnapshot`·`applySnapshot`), 어떻게 비우고(`clearData`), 무엇을 구독하는지(`subscribe`·`unsubscribe`)만 채우고, 쓰기는 `this.write(화면 반영, 서버 쓰기, 실패 문구)`로 한다. 규칙 자체의 테스트는 `tests/unit/synced-store.test.ts`.
- 모든 기능 화면은 로그인 직후부터 함께 올라가 있고, 현재 탭이 아닌 화면은 숨기기만 한다. 그래서 탭을 오가도 보던 달과 선택한 날짜가 남는다.
- 로그아웃 버튼은 각 탭 화면의 위쪽 줄 오른쪽 끝에 둔다(블로그는 새로고침 옆). 누르면 `src/core/session.svelte.ts`로 요청하고 `App.svelte`가 모든 기능을 정리한다. 새 탭도 같은 방식으로 버튼을 둔다. 세션이 만료되거나 다른 곳에서 로그아웃돼도 로그인 화면으로 돌아간다.
- 맨 아래 줄의 "실시간/끊김"은 지금 보는 탭의 연결 상태다.
- "오늘"은 `src/core/clock.svelte.ts`가 화면이 다시 보일 때와 1분마다 확인해, 자정이 지나면 오늘 표시가 따라간다.
- 접근성: 날짜 칸은 날짜·분야·담당·주제·다음 단계를 말로 읽어 준다. 모달은 열리면 포커스가 안으로 들어가고, Esc로 닫으며, 닫으면 눌렀던 칸으로 돌아간다. 탭은 탭 화면과 연결돼 있다.
- 마지막으로 보던 탭은 기기에 기억한다. 기억해 둔 탭이 없어졌으면 기본 탭(블로그)으로 열린다.
- 탭 화면은 하단 줄 위까지만 차지한다. 앱 전체 스크롤이 없다는 규칙은 모든 탭에 같다.

### 화면
- 달력이 메인이고 항상 켜져 있다. 블로그는 하나다.
- 태블릿형: 좌측 달력, 우측 아이템 항목. 모바일형: 화면 중앙에 달력, 날짜를 누르면 모달로 아이템을 보여준다.
- 두 형태는 화면 폭으로 나눈다. 폴드8은 접으면 모바일형, 펼치면 태블릿형이다.
- 달력 칸에는 분야와 주제만 글자로 보인다. 나머지는 눌러야 보인다.
- 분야·주제 글자 크기는 절대값이 아니라 **칸의 가로·세로를 재서** 정한다(`src/features/blog/cell-font.ts`). 기본은 칸 안쪽 폭의 1/6(한글 6글자가 한 줄)이다.
  폰처럼 칸이 홀쭉해서 기본값이 8px보다 작아지면, 칸이 허락하는 만큼(한 줄 4글자 이상, 세로 4줄 이상) 키워서 8px를 지킨다. 이미 8px 이상인 칸(폴드 안쪽, 태블릿)은 기본값 그대로다. 위쪽 한도는 24px.
  화면 크기가 바뀌거나 주 수(4~6줄)가 바뀌면 다시 잰다.

### 하루 아이템
날짜 하나에 아이템 하나다. 필드는 이 순서다.

1. 분야: 레시피,제품 / 뷰티 / 맛집,여행
2. 담당: 행이 / 챙이
3. 주제: 문자열
4. 사진촬영, 글작성, 글보정, 연관글, 예약: 모두 bool, 기본값 false

**잠금**: 앞 필드가 채워지지(true가 되지) 않으면 뒤 항목은 체크할 수 없다.
앞 항목을 해제하려는데 뒤에 true가 있으면 **해제 자체를 막는다.** 뒤 항목을 먼저 풀어야 한다.

### 분야 기본값
- 11월 8일을 "레시피,제품"으로 두고 3개가 하루씩 번갈아 돈다. 8일 이전 날짜도 같은 순서로 거슬러 계산한다.
- 날짜별로 수동으로 바꿀 수 있고, 바꾼 값은 그 날짜에만 남는다. 이후 날짜를 다시 계산하지 않는다.
- 기본 순환 규칙을 나중에 바꿔도 **지난 날짜는 그대로**다. "이 날짜부터 새 규칙"으로 이력을 남긴다. 설정 화면은 만들지 않는다.

### 칸 색
칸은 항상 단일색이다. 겹치는 색은 없다. 아래 순서로 먼저 맞는 것을 쓴다.

1. 예약 true → 회색 (회색은 예약 전용이다)
2. 글보정 true → 하늘색 (Blue)
3. 글작성 true → 분홍 (Pink)
4. 담당이 있으면 행이는 하늘색 (B), 챙이는 분홍 (P). 주제가 있는지, 사진을 체크했는지는 색을 바꾸지 않는다.
5. 분야만 있고 담당이 없으면 흰색
6. 연관글은 색에 영향이 없다.

색만으로 구분이 어려우니 칸 색에 맞춰 글자를 작게 붙인다. 하늘색 칸은 "행이", 분홍 칸은 "챙이"다. 담당이 아니라 **지금 칸 색**을 따르므로, 글작성(분홍)·글보정(하늘색) 단계에서는 담당과 다른 글자가 붙을 수 있다. 회색·흰색 칸에는 붙이지 않는다.

### 칸 하단의 다음 단계
- 시작한 날짜(담당·주제·체크 중 하나라도 있는 날짜)의 칸 맨 아래에 **다음에 해야 할 단계**가 `사진촬영`처럼 뜬다.
- 순서는 담당 → 주제 → 사진촬영 → 글작성 → 글보정 → 연관글 → 예약이고, 아직 안 한 첫 단계를 보여 준다. 이름은 줄이지 않고 항목 패널과 같은 원문(담당, 주제, 사진촬영, 글작성, 글보정, 연관글, 예약)을 쓴다. 칸이 좁아서 표시 글자 크기를 칸 폭에 맞춘다.
- 분야만 있는 날짜와 예약까지 끝난 날짜에는 표시하지 않는다.
- 어떤 칸 색(하늘색·분홍·흰색·회색) 위에서도 눈에 띄도록 어두운 바탕에 밝은 노랑 글자로 그린다.

### 달 넘기기
- 달력을 좌우로 크게 쓸면 달이 넘어간다. 왼쪽으로 쓸면 다음 달, 오른쪽으로 쓸면 이전 달이다. 달력 폭의 1/4(최소 80px) 이상 옆으로 밀어야 하고, 위아래로 밀린 것보다 1.5배 이상 옆으로 가야 한다.
- 터치는 길게 누르지 않고 바로 밀면 쓸어 넘기기이고, 길게 누른 뒤 끌면 아이템 이동이다. 마우스로 내용 있는 칸을 잡으면 아이템 이동이고, 빈 칸에서 밀면 쓸어 넘기기다.
- 이전/다음 달 버튼과 오늘 버튼은 그대로 쓸 수 있다.

### 날짜 이동 (드래그 앤 드롭)
- 아이템은 다른 날짜로 끌어서 옮긴다. 터치는 길게 눌러 끌기로 하고, 모달에도 날짜 이동 버튼을 둔다.
- **분야도 아이템과 함께 따라간다.** 도착 날짜의 분야가 옮긴 아이템의 분야로 바뀐다.
- 떠난 날짜는 담당·주제·체크가 초기화되고, **분야는 옮겼던 값 그대로 남는다.**
- 도착 날짜에 주제가 있으면 이동을 막는다. 담당까지만 있으면 덮어쓴다.

### 저장과 기술
- 날짜별 분야는 모두 저장한다. 순환 규칙은 빈 날짜를 처음 열 때 분야를 채우는 데만 쓴다. 이동으로 분야가 복제되기 때문이다.
- 순환 규칙은 `blog_category_rules`에 이력으로 둔다(`effective_from`, 기준일, 순서). 스키마는 `supabase/migrations/0002_blog.sql`.
- 화면은 먼저 바꾸고 서버에는 나중에 보낸다. 서버에 쓰는 일은 한 줄로 세워 **누른 순서대로** 보낸다(`src/core/write-queue.ts`).
  쓰는 동안 들어온 실시간 알림과 다시 불러오기는 무시하고, 다 끝나면 한 번만 다시 불러온다.
  이렇게 하지 않으면 연달아 누른 값이 서버에서 뒤집히거나, 돌아온 알림이 방금 바꾼 화면을 옛 값으로 덮는다.
- 날짜 이동은 두 행을 한 번에 바꿔야 해서 `move_blog_day(from, to)` 함수로 처리한다.
- 날짜를 기본키로 한 행 하나에 아이템 하나를 둔다. 필드는 JSONB가 아니라 일반 컬럼이다. 항목이 늘면 컬럼을 추가한다.
- RLS와 Realtime은 기존 접속 기록 테이블과 같은 방식이다.
- 화면 프레임워크는 Svelte(Vite)다.
- 알림과 오프라인 쓰기는 이번 범위에서 뺀다. 달력이 돌아간 뒤 필요하면 붙인다.

## 확정한 것: 냉장고

### 화면
- 메인은 위(냉장고)·가운데(냉동고)·아래(실온) 세 구역이다. 냉장고와 냉동고는 높이가 같고 각각 좌우 두 칸(냉장고는 신선/양념, 냉동고는 재료/밀키트)이며, 실온은 조금 낮고 칸이 하나뿐인 "실온 보관"이다. 실온에는 다른 구분이 없다.
- 칸을 누르면 블로그 아이템 화면처럼 열린다. 넓은 화면은 오른쪽 패널(처음엔 냉장고·신선), 좁은 화면은 모달이다. 모달 공통 동작은 `src/ui/Modal.svelte`.
- 메인의 칸에는 오래된 재료부터 칸 높이가 허락하는 줄 수만큼 보인다(줄 높이 20px로 센다). 넘치면 마지막 줄이 "+N개"가 된다.
- 위쪽 줄의 월 변경 자리에는 "구매목록" 버튼이 있다. 체크 안 한 항목 수가 배지로 붙는다. 그 오른쪽에 "식단" 버튼이 있다.

### 재료
- 필드는 이름(40자까지), 추가된 날짜(시간 없이 날짜만, 기본 오늘, 고칠 수 있음), 개수(선택, 단위 없음)다. 이름이 같은 재료도 따로 둔다. 이미 넣은 재료의 날짜도 칸 화면에서 날짜 글자를 눌러 달력으로 바꿀 수 있고, 바꾸면 정렬 순서도 따라간다.
- 날짜는 연도까지 쓰고(칸 화면 `2026-11-08`, 메인 `26/11/8`), 오늘까지 지난 날수를 `5일`·`오늘`로 함께 보여준다. 메인 칸은 좁으면 지난 날수만, 칸 폭이 190px 이상이면 날짜도 보인다.
- 칸 화면의 추가 입력(이름·날짜·개수·추가 버튼)은 한 줄이고, 입력 세 칸은 폭이 같다. 목록의 재료도 한 줄(이름 · 날짜와 지난 날수 · 개수 · 삭제)이다.
- **개수 없음도 정상 재료다.** 비활성이 아니다. 개수는 1 이상 999 이하의 정수만 받는다.
- 늘리기: 개수 없음 → 1, 이후 +1. 줄이기: 1에서 줄이면 개수 없음으로 돌아가고, 개수 없음에서는 줄이기 버튼이 눌리지 않는다. 입력칸에 직접 쓰거나 비워도 된다.
- 정렬은 추가된 날짜가 오래된 순이다. 날짜가 같으면 먼저 넣은 재료가 앞이다. 메인과 칸 화면이 같은 기준이다.
- 삭제는 두 번 눌러야 한다. 첫 번째 누름은 ✕를 빨간 "삭제"로 바꾸고(3초 안에 다시 눌러야 하며, 다른 곳을 누르면 취소), 두 번째 누름이 지운다. 삭제 버튼은 개수 버튼과 떨어져 있고 확인 상태에서도 폭이 같다. 재료 이름 수정은 만들지 않았다(지우고 다시 넣는다).

- 칸 화면과 구매목록 창은 크기가 고정이다(높이 560px, 화면이 낮으면 화면에 맞춤). 재료가 늘고 줄어도 창과 입력 줄의 위치가 변하지 않고, 재료 목록만 안에서 스크롤한다. 넓은 화면의 오른쪽 패널도 같다.

### 구매목록
- 모달 하나. 맨 위 입력 한 줄 + 엔터로 추가하고, 항목은 두 열로 촘촘히 놓는다. 눌러서 체크하면 아래로 내려가고, 줄마다 ✕로 지운다. 체크한 항목은 위쪽의 "체크 N개 삭제" 한 번으로 지운다.
- DB에 저장하고 실시간으로 기기끼리 같이 본다.

### 식단
- "식단" 버튼을 누르면 달력 모달이 뜬다. 달력의 날짜 칸에는 적어 둔 점심("점")·저녁("저")이 한 줄씩 보이고, 날짜를 누르면 아래에서 그날의 점심·저녁을 적는다(처음엔 오늘). 입력칸은 엔터나 포커스를 벗어날 때 저장하고, 비우면 그 끼니가 지워진다. 월 이동 버튼과 "오늘" 버튼이 있다.
- 냉장고 재료와 이어지지 않는 자유 메모다(40자까지). 점심·저녁이 모두 비면 그날의 행을 지운다.
- 테이블은 `meal_plans`(`supabase/migrations/0007_pantry_meals.sql`). 날짜가 기본키(사용자별)라서 하루에 한 행이다. 저장 방식은 재료·구매목록과 같고 같은 스토어(`fridge`)가 맡는다.

### 저장과 기술
- 테이블은 `fridge_items`, `shopping_items`(`supabase/migrations/0003_fridge.sql`). id와 생성 시각은 앱이 만들어 보낸다(화면을 먼저 바꾸기 때문).
- 칸 이름은 DB에 `fridge_fresh`·`fridge_sauce`·`freezer_ingredient`·`freezer_mealkit`·`pantry`로 저장한다(`pantry`는 0007에서 더했다). 규칙은 `src/features/fridge/domain.ts`, 스키마와의 일치는 `tests/unit/schema-parity.test.ts`가 확인한다.
- 쓰기와 실시간 처리 방식은 블로그와 같다(`WriteQueue`).

## 확정한 것: 가계부

단계별 구현 계획은 [docs/ledger-plan.md](ledger-plan.md). 아래는 화면과 규칙 중 확정한 것이다. 지금은 2단계(DB 연동)와 문자함의 저장 구조까지 만들었다. 항목·카드·분류·예산 규칙·문자함이 모두 Supabase에 저장되고 기기끼리 실시간으로 맞는다. 문자는 안드로이드 앱(APK)이 폰의 문자함에서 읽어 오고(아래 "안드로이드 앱"), 값 읽기 규칙은 아직 임시다.

### 화면
- 위쪽 줄: 달 넘기기(‹ 2026년 11월 ›, 달 제목을 누르면 이번 달로), "불러오기", 로그아웃. 카드·발신번호 등록은 설정 탭에 있다. 폭 360px에서도 한 줄에 들어간다.
- **가계부 안에 탭이 넷 있다: 목록 · 결산 · 통계 · 설정.** 둘째 줄 왼쪽의 알약 버튼으로 오가고, 오른쪽 끝의 "+ 지출 추가"는 어느 탭에서나 보인다. 큰 화면에서도 한 번에 한 탭만 보이며 내용 폭은 760px로 제한해 가운데에 둔다. 위쪽의 달 넘기기는 목록·결산·통계에 적용되고(통계는 고른 달이 그래프의 끝), 설정은 달과 무관하다.
- 설정은 앱 하단의 탭이 아니라 가계부 안의 탭이다. 앱 하단 탭은 블로그·냉장고·가계부 셋이다.
- 표의 색은 `src/style.css`의 `--table-head`(머리글), `--table-band`(날짜 띠·띠 제목), `--row-hover`(누를 수 있는 줄에 올렸을 때)다. 목록의 표와 결산·통계·설정의 "표 한 장"(`.sheet`, `.band`)이 같은 색을 쓴다.

### 목록 탭
- **맨 위에 예산 요약**이 있다. 첫 줄에 예산 · 합계 · 차액 세 값을 한꺼번에 보이고(칸 사이에 선), 아래 줄에는 사용률 막대만 있다. 예산을 정하지 않은 달은 예산과 차액이 "-"이고 막대는 비어 있다. 초과하면 차액에 "-"가 붙은 빨간 금액과 빨간 막대로 나타낸다(색만으로 알리지 않는다).
- **목록은 둥근 카드가 아니라 표 하나다.** 열은 분류 · 메모 · 구분 · 금액이고, 열 머리글 줄은 스크롤해도 위에 남는다. 날짜가 바뀌는 자리마다 진한 띠 행이 있고(날짜와 요일, 같은 줄 오른쪽 금액 칸에 그날 합계), 그 아래에 항목 줄이 이어진다. 줄 어디를 눌러도 고치는 창이 열린다. 줄이 적으면 표가 내용 높이만큼만 차지한다.

### 결산 탭
- 한 달 정리다. 위에서부터 이 달 합계(금액 하나만, **예금을 합친 값**이고 아래 설명 문구는 두지 않는다), 예산(보기만, 입력은 설정 탭), 분류별, 구분별이다. 막대는 금액 하나뿐인 단일 계열이라 강조색 하나로 얇게 그리고, 글자는 본문 색이다. 비율은 지출(양수) 합계에 대한 것이다.
- **분류별·구분별 줄을 누르면 그 묶음의 이번 달 이력이 창으로 뜬다.** 창은 목록과 같은 표(날짜 띠 포함)이고 제목에 건수와 합계가 있다. 보기만 하며 여기서 고치지는 않는다. 달을 바꾸면 그 달 이력이 된다.

### 통계 탭
- 고른 분류(또는 전체)가 **최근 12개월** 동안 어떻게 변했는지 보여 준다. 끝은 위쪽에서 고른 달이다. 분류는 칩으로 고른다.
- 막대 그래프와 같은 값의 표(월 · 금액 · 전월 대비 ▲▼, 월 평균)가 함께 있다. 막대는 한 가지 색이고 고른 달만 진하다. 12개월이라 값을 모든 막대에 적으면 겹치므로 **가장 높은 달과 고른 달만** 막대 위에 `5.6만` 같은 짧은 금액으로 적고(두 달이 이웃하면 고른 달 글자를 뺀다), 나머지 값은 표로 본다.
- 그래프 첫 달의 전월 대비는 그래프 밖의 지난달과 비교한다. 두 달 모두 기록이 없으면 "-"이다. 설정에서 뺀 분류라도 이력이 있으면 칩에 남는다.

### 설정 탭
- 가계부의 예산, 분류, 카드·발신번호를 다룬다. 표 세 장(예산, 분류, 카드 · 발신번호)이 위아래로 있고 내용이 길면 이 안에서만 스크롤한다.
- **화면에 설명 글을 두지 않는다.** 적용 범위 이름과 입력 칸, 정해 둔 목록만 둔다(자리를 차지하기 때문이다).
- **구분(현금·카드)은 설정에서 정하지 않는다.** 카드는 이 탭의 "카드 · 발신번호" 표에서 등록하고, 구분은 그 카드를 따라간다.
- **분류**: 이름(10자까지)을 적어 더한다. 분류는 **칩**으로 가로로 흘러 세로로 길어지지 않고(폭 360px에서 한 줄에 셋쯤), 칩 하나가 손잡이(⋮⋮) · 이름 · 지우는 ✕ 버튼이다. **손잡이를 끌어 놓으면 순서가 바뀐다**(터치도 된다. 손잡이에서 방향키로 한 칸씩도 옮긴다). 이 순서가 `ledger_categories.position`에 저장되고, 지출 추가의 분류 선택지와 통계의 분류 칩이 같은 순서를 따른다. ✕를 한 번 누르면 칩 안에서 빨간 "삭제"로 바뀐다. 이름이 비었거나 겹치면 받지 않는다. **지워도 이미 적은 지출은 이름 그대로 남는다.** 선택지에서만 빠지고, 그 분류로 적은 항목을 고칠 때는 그 이름이 선택지에 남는다. 분류는 하나 이상 있어야 해서 마지막 하나는 지울 수 없다. 새 항목의 기본 분류는 "기타"가 있으면 기타, 없으면 첫 분류다.
- **예산**: 띠 제목 오른쪽에 "이번 달 X원", 그 아래에 적용 범위(기본값 변경 / 해당 월만 / 해당 월 이후), 달 고르기(범위가 기본값이면 숨김), 금액 입력, "적용" 버튼이 있다. 아래 "정해 둔 예산" 목록에 정한 규칙이 보인다.

### 예산 규칙
- 차액 = 예산 − 지출 합계이고 취소(음수)는 지출에서 빠진다. 예산과 꼭 같으면 초과가 아니다. 결산에서는 초과를 "14,400원 초과"로 쓴다.
- 예산은 설정 탭에서 정하고, **세 가지 규칙**이 있다. 한 달의 예산은 ① 그 달만 정한 값, ② 없으면 그 달 이전에 "해당 월 이후"로 정한 것 중 가장 최근 값, ③ 없으면 기본값 순으로 정해진다. 아무것도 없으면 예산이 없다.
  - **기본값 변경**: 따로 정하지 않은 모든 달에 쓰는 값. "해당 월 이후" 규칙이 있는 달부터는 그 규칙이 먼저다.
  - **해당 월만**: 고른 한 달만 바꾼다. 앞뒤 달은 그대로다.
  - **해당 월 이후**: 고른 달부터 다음 변경까지 값을 바꾼다. 이전 달은 그대로라서 예산을 올려도 지난 달 기록의 차액이 바뀌지 않는다.
- 예산 금액은 1 이상의 정수만 받는다. "해당 월 이후"와 "해당 월만" 규칙은 두 번 눌러 지운다. 기본값은 지우지 않고 값만 바꾼다.

### 지출 추가·고치기
- 냉장고와 같은 방식이다. 삭제는 두 번 눌러야 한다(3초 안에). 두 번 눌러 지우는 버튼은 `src/ui/ConfirmButton.svelte`가 하나로 맡는다(가계부에서 쓴다. 냉장고는 기존 코드를 그대로 둔다).

### 항목
- 필드는 날짜, 구분, 분류, 금액, 메모(100자까지)다. 예산은 항목이 아니라 달별 설정이다.
- 구분은 "현금" 또는 등록한 카드 이름이다. 분류는 처음에 식비·교통·쇼핑·생활·의료·문화·기타이고, 이후에는 가계부의 설정 탭에서 더하고 뺀다.
- 금액은 원 단위 정수이고 0은 받지 않는다. **승인 취소·환불은 음수**로 적고, 합계에서 빠진다.
- 정렬은 날짜가 최근인 순, 같은 날은 나중에 넣은 항목이 위다.
- **"예금"은 합계에 넣지 않는 고정 분류다**(`domain.ts`의 `SAVINGS_CATEGORY`). 지출이 아니라 저축이기 때문이다. 설정에서 지울 수 없고(칩에 ✕ 대신 🔒), 순서는 바꿀 수 있다. 다음에서 빠진다: 목록 위 예산 요약의 합계·차액, 날짜 띠의 하루 합계, 결산의 분류별·구분별과 예산 칸의 지출 합계, 통계의 "전체". 단 **결산 맨 위의 "이 달 합계"만 예금을 합친다.** **결산의 예산 칸 마지막 줄에 "예금" 합계를 따로 두고**(예산을 정하지 않은 달에도 보인다. 그 달에 예금 항목이 없으면 줄은 그대로 두고 금액 칸만 비운다) 누르면 예금의 이력 창이 열린다. 항목은 목록에 그대로 보이고, 통계에서 "예금" 칩을 직접 고르면 예금의 추이를 볼 수 있다. 이 분류는 앱이 이름으로 알아보며, 설정에서 "예금"을 더해 두어야 쓸 수 있다.

### 문자 불러오기와 문자함
- **카드 · 발신번호**는 설정 탭에서 등록한다(이름과 발신번호). 번호는 숫자만 남긴다. 견본은 사용자가 직접 붙여 넣지 않고, 아래처럼 문자를 처리하면서 쌓인다.
- **등록한 번호로 온 문자만 읽는다.** 다른 문자는 읽지 않는다. 카카오톡 알림은 읽지 않는다.
- **문자함(`ledger_sms`)**: 불러오기를 누르면 등록한 번호로 온 **최근 30일치 문자를 전부** 문자함에 쌓는다. 결제와 무관한 문자(광고·안내)도 쌓는다. DB를 적게 쓰려고 기간은 30일로 고정하고(`SMS_KEEP_DAYS`), 불러올 때마다 30일이 지난 문자를 지운다(쌓지도 않는다). 한 통의 상태는 `처리 필요 / 완료 / 무시` 셋이다.
- 같은 문자는 식별값(`sms_key`)이 같아 두 번 쌓이지 않고, 다시 불러와도 **완료·무시한 상태가 처리 필요로 돌아가지 않는다.** 항목이 그 문자를 가리키고 있으면(완료 표시를 서버에 쓰다 실패한 경우) 처리한 것으로 본다. 새 문자가 없으면 "처리할 문자가 없다."를 알린다. 카드를 하나도 등록하지 않았으면 설정 탭으로 보낸다.
- **창**: "불러오기" 뒤 "처리 필요" 문자 목록이 열린다(`SmsInbox`). 줄(가맹점·금액·날짜·구분, 못 읽었으면 본문)을 누르면 **양식**(`SmsForm`)이 열린다. 양식은 위에 문자 본문을 보여 주고 날짜·구분·금액·메모에 문자에서 읽은 값을 먼저 채우며, 읽지 못한 값은 비워 둔다. **분류는 정해 두지 않고, 직접 고르기 전에는 "추가"가 눌리지 않는다.** 추가하면 그 문자가 완료가 되고 목록으로 돌아간다. 처리할 문자가 더 없으면 창이 닫힌다.
- **무시**: 추가하지 않을 문자는 목록의 줄이나 양식에서 "무시"로 치운다. 무시한 문자도 다시 불러와도 나오지 않는다. 목록 아래의 "무시한 문자 N건 되돌리기"가 무시한 문자를 모두 처리 필요로 되돌린다(초기화).
- **견본**: 양식에서 추가할 때 사용자가 확정한 값이 자동 채움과 다르거나 자동 채움이 비어 있었으면, 그 문자를 견본으로 그 카드의 `ledger_cards.samples`에 쌓는다(`{본문, 확정한 값}`, 카드당 20개까지, 추가했다는 알림에 "견본으로 저장했다"가 붙는다). 자동 채움이 맞아서 그대로 추가한 문자는 견본을 늘리지 않는다. **문자 본문에 글자 그대로 있는 값만** 견본에 담는다(금액 `5,600`·`5600`, 날짜 `11/13`·`2026.11.13`·`11월 13일` 등, 가맹점은 본문 속 글자). 문자에 없는 값(가맹점을 다르게 적은 것 등)은 그 항목에만 쓰고, 금액이 본문에 없으면 견본을 만들지 않는다. 값만 다른 같은 모양의 문자(숫자와 값 자리를 자리표시로 바꾼 모양이 같은 것)가 이미 있으면 늘리지 않는다(`domain.ts`의 `newSample`). 견본에서 자동 채움 규칙을 만드는 일은 아직 없다. 견본이 쌓인 뒤에 만든다.
- **문자를 읽어 오는 건 안드로이드 앱뿐이다.** 웹(PC·브라우저·PWA)에서 "불러오기"를 누르면 폰이 문자함에 쌓아 둔 "처리 필요" 문자를 열어 준다(없으면 "처리할 문자가 없다"). 문자함과 견본은 서버에 있어서 어느 기기에서든 보고 추가할 수 있다. 실제 문자를 받아 오면 처음에는 값이 거의 비어 있으므로 직접 채워 견본을 쌓는다. 값 읽기(`sms-guess.ts`의 `guessFromSms`)는 먼저 그 카드에 쌓인 **견본의 틀**에 맞춰 보고(사용자가 고쳐 둔 값이 이긴다), 맞는 틀이 없으면 아는 모양으로 읽는다. 견본의 틀은 견본 본문에서 금액·날짜·가맹점이 적힌 자리만 비우고, 나머지 글은 그대로 두며 숫자는 어떤 숫자든, 공백은 어떤 공백이든 맞게 만든 식이다(전체가 맞아야 한다). 취소 견본(금액이 음수)의 틀은 금액이 음수로 나온다. 아는 모양은 두 가지다: "승인|취소 5,600원 가맹점 11/13" 한 줄 모양, 그리고 카드사 안내 모양(우리·NH카드: "…승인 / 5,000원 일시불 / 11/12 17:33 / 가맹점" 줄이 이어지며, 날짜·시각 줄을 기준으로 앞에서 금액을 뒤 첫 줄에서 가맹점을 읽고 "취소"가 있으면 금액이 음수다). 가맹점에는 누적금액("누적…")을 붙이지 않는다.
- 문자 본문은 **2000자까지만** 쌓는다(DB 상한, `SMS_BODY_MAX`). 넘으면 잘라서 쌓는다. 문자 한 통이 상한에 걸려 다른 문자까지 못 쌓게 되는 일을 막으려는 것이다. 문자의 날짜는 받은 시각을 **기기 시간대 날짜**로 바꿔 쓴다(UTC 날짜가 아니다).
- 읽는 범위는 **최근 30일**(문자함 보관 기간과 같다)이고, 사용자가 "불러오기"를 눌렀을 때만 읽는다. 문자 식별값은 `번호:받은 시각:본문 해시`라서 어느 기기에서 읽어도 같은 문자는 같은 값이다(`sms-reader.ts`의 `smsKey`).

### 안드로이드 앱 (문자 읽기)
- 웹 앱은 문자를 읽을 수 없어서 **Capacitor 안드로이드 앱(APK)** 이 필요하다. APK는 화면을 담지 않고 배포 주소(`https://markok337.github.io/hece_note/`)를 연다(`capacitor.config.ts`의 `server.url`). 그래서 화면·규칙·견본이 바뀌어도 APK는 다시 설치하지 않는다. APK를 다시 설치하는 경우는 껍데기(권한, 플러그인)가 바뀔 때뿐이다.
- 폰의 문자함을 읽는 일은 **직접 만든 작은 플러그인**(`android/.../SmsInboxPlugin.java`, 이름 `SmsInbox`)이 한다. 외부 플러그인은 쓰지 않는다(관리가 끊기거나 필요 없는 권한이 붙을 수 있다). 권한은 `READ_SMS` 하나이고, 등록한 발신번호의 문자만 앱에 넘긴다(다른 번호의 문자는 조회 결과에서 바로 버린다). 문자를 보내거나 지우지 않는다. `+82` 형식으로 온 번호는 `0`으로 시작하는 국내 형식으로 바꿔 비교한다.
- 문자함은 일반 문자(`content://sms/inbox`)와 장문·사진 문자(`content://mms`, 본문은 `mms/part`의 text/plain, 보낸 쪽은 `mms/<id>/addr`의 type 137)를 모두 읽는다. 카드 승인 문자는 길면 LMS로 와서 MMS 저장소에 들어가기 때문이다. 기관이 보내는 RCS(삼성 메시지의 "대화" 메시지, 보낸 쪽에 "확인된 발신번호"가 붙는 것)는 삼성 전용 저장소 `content://im/chat`(열 `address`·`date`·`body`·`type`, `type` 2는 보낸 것)에 있고 문자 권한만으로 읽힌다. 삼성 메시지가 아닌 기기에서는 이 저장소가 없어 건너뛴다. 이 저장소의 `body`는 화면 모양을 적은 JSON(`layout`의 `TextView.text`에 문자 내용이 있다)이라서, 글만 순서대로 모아 일반 문자처럼 풀어 저장한다(`domain.ts`의 `plainBody`). RCS 본문은 JSON 모양이 둘이다: `layout`의 `TextView.text`(우리카드), `message.generalPurposeCard.content.description`(NH카드, 줄바꿈 `\r\n`). 문자 식별값은 원본 본문으로 만들어 이미 쌓인 문자와 겹치지 않고, 이미 쌓인 JSON 본문도 화면에서 풀어 보인다. `+82`로 저장된 번호는 국내 형식으로 되돌려 비교한다(8자리 대표번호는 0을 붙이지 않는다).
- 불러오기에서 등록한 번호의 문자가 한 건도 없으면 점검 문구로 문자함의 최근 30일 전체 건수와 번호별 건수를 보여 준다(`summary`, 본문은 읽지 않는다). 카드 문자가 일반 문자함에 없는지(RCS·알림톡 등) 번호만 다른지 가리려는 것이다.
- 플레이스토어에는 올리지 않는다(문자 읽기 권한을 정책상 허용하지 않는다). 폴드8, S26에 직접 설치한다.
- 앱을 만드는 방법과 권한 허용 절차는 [setup.md의 "8. 안드로이드 앱 만들고 설치하기"](setup.md).

### 가계부 실적 표시
- 지출에 `perf`(체크)를 둔다. 한 달에 쌓아야 하는 개수는 `PERF_GOAL`(10)로 고정이고, 그 달(지출 날짜 기준)에 `perf`가 켜진 항목 수를 `perfCount`가 센다. 금액은 보지 않는다.
- 보이는 곳: 지출 양식·문자 양식의 체크, 목록 줄의 메모 앞 ✓, 목록 위 요약의 "실적 N/10", 결산의 "실적 N / 10개". DB는 `0006_ledger_perf.sql`.
