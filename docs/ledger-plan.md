# 가계부 구현 계획

가계부 탭은 카드 결제 문자를 불러와 지출로 기록한다. 화면과 규칙 중 확정한 것은 [decisions.md의 "확정한 것: 가계부"](decisions.md)에 있다. 이 문서는 아직 만들지 않은 단계만 적는다.

**1단계(화면 시안)는 끝났다.** 메모리 저장, 모의 불러오기까지다. 아래 2~4단계는 순서대로 진행하고, 단계가 끝날 때마다 `decisions.md`의 해당 문장("1단계의 불러오기는 모의다" 등)을 현재 상태로 고친다.

## 2단계: DB 연동

화면이 부르는 `ledger` 스토어의 메서드 모양은 그대로 두고, 저장만 Supabase로 바꾼다.

- `supabase/migrations/0004_ledger.sql`: 테이블 둘.
  - `ledger_entries`: id, spent_on(date), method(text), category(분류 7가지 check), amount(integer, 0 제외, 절댓값 10억 이하), memo(100자 이하), sms_key(text, 없으면 null), created_at, user_id.
  - `ledger_cards`: id, name(20자 이하), sender(숫자 3~15자리), samples(text 배열), created_at, user_id.
  - `(user_id, sms_key)`는 sms_key가 있을 때만 유일하게 한다. 같은 문자를 두 번 가져와도 DB가 막는다.
  - `(user_id, sender)`, `(user_id, name)`도 유일하다.
  - RLS는 냉장고와 같이 `owner_all`, Realtime 등록도 같다.
- `repo.ts`: 냉장고 `repo.ts`와 같은 모양(fetch·upsert·delete·subscribe).
- `store.svelte.ts`: `WriteQueue`로 낙관적 쓰기와 실시간 반영, 실패하면 서버 값으로 되돌림. `live`가 실제 연결 상태를 따라가므로 하단 표시가 "실시간"이 된다. 문자 확인 상태(`dismissed`)도 DB에 저장해 기기끼리 맞춘다(읽지 못한 문자를 다른 기기에서 다시 보지 않도록).
- 테스트: 냉장고 스토어 테스트와 같은 방식(repo를 mock), `schema-parity.test.ts`에 분류 목록과 check 일치 검증 추가.
- 사용자가 할 일: Supabase SQL Editor에서 0004를 실행한다(`docs/setup.md`의 방식).

## 3단계: 문자 규칙 (견본으로 읽는 법 정하기)

카드사 문자 모양을 코드에 박지 않고, 카드를 등록할 때 넣은 견본에서 앱이 읽는 규칙을 만든다.

- `parse.ts`(순수 함수): 문자 한 건에서 금액, 가맹점, 날짜·시각, 승인/취소를 뽑는다. 기준은 견본이다.
- 견본 등록 화면에서 견본마다 "금액·가맹점·날짜·승인/취소" 위치를 사용자가 글자를 눌러 지정한다. 앱은 금액(`숫자원`), 날짜(`11/13`, `2026.11.13`) 같은 흔한 모양을 먼저 짐작해서 보여 주고, 틀리면 사용자가 고친다. 지정한 결과를 그 번호의 규칙으로 저장한다(`ledger_cards`에 규칙 컬럼 추가, 마이그레이션 0005).
- 한 번호에 견본을 여러 개 둘 수 있다(결제·취소·해외결제 등). 규칙에 맞지 않는 문자는 지출로 만들지 않고 "읽지 못한 문자"로 보낸다. 모양이 바뀐 문자가 조용히 빠지거나 엉뚱한 금액으로 들어가지 않게 하려는 것이다. 읽지 못한 문자를 눌러 견본으로 추가하면 규칙이 늘어난다.
- 문자에 연도가 없으면 문자를 받은 시각의 연도를 쓴다. 연말·연초 경계(12월 문자를 1월에 읽는 경우)를 테스트한다.
- 취소는 음수 금액 항목으로 들어간다.
- 테스트: 견본(가짜 문자) 몇 종류로 결제·취소·읽지 못함·날짜 모양·금액 쉼표·연도 경계. 실제 카드번호·이름은 테스트에 넣지 않는다.

## 4단계: 안드로이드 앱(APK)과 실제 문자 읽기

- **껍데기 APK**: Capacitor로 만들고, 앱이 배포 주소(`https://markok337.github.io/hece_note/`)를 열게 한다(`server.url`). 화면 코드는 APK에 넣지 않으므로 화면 업데이트는 배포만으로 끝난다. 폴드8, S26에 직접 설치한다. 플레이스토어에는 올리지 않는다(문자 읽기 권한을 정책상 허용하지 않는다).
- **문자 읽기**: 안드로이드 `READ_SMS` 권한으로 문자함을 조회하되, 등록한 발신번호의 문자만 조회한다. 쓸 플러그인(또는 직접 만든 작은 플러그인)은 이 단계 시작 때 조사해서 정한다. 이 문서에서는 정하지 않는다.
- **권한 안내**: 직접 설치한 앱은 안드로이드 13 이후 문자 권한이 막혀 있다. 앱 정보에서 "제한된 설정 허용"을 켜고 문자 권한을 줘야 한다. 이 절차를 `docs/setup.md`에 적는다.
- **불러오기 버튼**: `mock-sms.ts`의 `fetchMockSms` 자리에 실제 읽기 함수를 같은 반환 모양(`candidates`, `unparsed`)으로 꽂는다. APK 안에서 열렸는지 확인해, 아닐 때(PC·노트북의 PWA)는 버튼을 숨기거나 비활성화하고 이유를 안내한다. 어느 기기에서 열어도 코드는 하나다.
- **읽는 범위**: 마지막으로 불러온 시각 이후의 문자만 읽는다. 처음 한 번만 읽을 기간(예: 이번 달 1일부터)을 정한다.
- **자동으로 불러오지 않는다.** 사용자가 버튼을 눌렀을 때만 읽는다.
- 확인: 폴드8·S26 실기기에서 권한 허용 → 불러오기 → 확인 창 → 추가 → PC 브라우저에 같은 항목이 뜨는지, 같은 문자를 다시 불러오면 건너뛰는지 본다.

## 정해야 할 것

- 분류 자동 추천: 가맹점 이름으로 이전에 정한 분류를 기억해서 확인 창에 미리 골라 줄지.
- 분류 목록 편집(추가·삭제·이름 바꾸기)을 만들지.
- 4단계의 처음 읽을 기간.
