# 독서 탭 구현 계획

## 확정한 요구사항

- 독서 탭의 중심 화면은 월간 달력이다.
- 책 한 권은 읽는 사람(행이 또는 챙이), 시작일, 선택 입력하는 종료일을 가진 기간 항목이다. 종료일이 없으면 시작일부터 현재까지 진행 중인 책으로 본다. 종료일을 입력하면 시작일과 종료일을 모두 포함해 달력에 표시한다.
- 책에는 제목, 글쓴이, 여러 개의 메모가 있다. 메모 하나에는 페이지와 내용이 있다. 모든 값은 사용자가 직접 입력한다.
- 매일 행이와 챙이의 독서 여부를 각각 체크한다. 이 기록은 책과 무관하며 날짜에만 속한다.
- 두 사람이 같은 책 목록과 일별 기록을 볼 수 있어야 한다.
- 두 사람이 같은 책을 읽어도 책 항목은 각자 따로 만든다. 메모는 해당 책 항목에 속하므로 메모별 작성자는 기록하지 않는다.
- 종료일이 없는 책은 오늘까지만 달력에 표시한다. 미래 날짜의 독서 체크는 허용하지 않는다.
- 완독 상태나 별도 버튼은 두지 않는다. 다 읽은 날을 종료일에 직접 입력한다.

## 화면과 조작

1. 기존 하단 탭 목록에 `독서`를 추가한다. 처음 열면 이번 달 달력을 보여주고 이전 달·다음 달·오늘 이동을 제공한다.
2. 날짜 칸에는 행이·챙이 체크박스와 해당 날짜를 포함하는 책의 제목·읽는 사람을 표시한다. 같은 날 책이 여러 권이면 모두 표시하되, 좁은 화면에서는 초과 권수를 표시하고 날짜 상세 화면에서 전체 목록을 보여준다.
3. 날짜를 누르면 그날의 체크 상태와 진행 중인 책 목록을 연다. 오늘과 지난 날짜의 체크박스는 날짜 칸이나 상세 화면에서 바로 바꿀 수 있다. 미래 날짜의 체크박스는 비활성화한다.
4. 책 추가 화면에서 읽는 사람, 제목, 글쓴이, 시작일을 입력하고 종료일은 비워둘 수 있다. 종료일을 입력했다면 시작일보다 빠를 때 저장을 막는다. 다 읽었을 때는 종료일을 직접 입력한다. 책 상세 화면에서 같은 필드를 수정하거나 책을 삭제한다.
5. 책 상세 화면에서 메모를 여러 개 추가·수정·삭제한다. 메모는 페이지와 내용으로 구성하고 입력 순서를 유지한다. 페이지는 수기로 적는 값으로 두어 `12`, `12~15` 같은 표기도 허용한다.
6. 모바일에서는 날짜·책 상세를 모달로, 넓은 화면에서는 달력 옆 패널로 보여주는 기존 화면 관례를 따른다. 기간이 여러 달에 걸치면 각 달에 걸친 날짜 모두에 책이 보인다. 종료일이 없는 책은 미래 날짜에 미리 펼치지 않고 오늘까지만 표시한다.

## 데이터와 동기화

1. 새 Supabase 마이그레이션에 `reading_books`(id, 읽는 사람, 제목, 글쓴이, 시작일, nullable 종료일, 생성·수정 시각), `reading_notes`(id, book_id, 페이지, 내용, 표시 순서), `reading_days`(day, 행이 체크, 챙이 체크)를 추가한다. 날짜 체크는 날짜당 한 행이며 책과 외래키로 연결하지 않는다.
2. 기존 앱의 로그인·RLS 정책과 맞춰 접근 권한을 설정한다. 책 삭제 시 소속 메모도 함께 삭제하고, 일별 체크는 유지한다.
3. 책은 조회 달력의 첫날~마지막 날과 기간이 겹치는 항목을 가져온다. 종료일이 비어 있으면 조회 시에는 진행 중인 책으로 포함하되 화면에는 오늘까지만 표시한다. 메모는 책 상세를 열 때 가져오거나 책과 함께 동기화한다. 날짜 체크는 표시 중인 달력 범위를 조회한다.
4. 다른 기기에서 바뀐 책·메모·일별 체크가 반영되도록 기존 기능과 같은 실시간 구독 및 재불러오기 흐름을 적용한다. 저장 실패 시 화면 상태를 복구하고 오류를 알린다.
5. `src/features/reading` 아래에 도메인·저장소·상태·화면을 분리하고 `src/tabs.ts`에 기능을 등록한다. 기존 날짜 계산 도구와 모달을 재사용한다.

## 구현 순서와 확인 기준

1. 기간 포함 여부, 달 경계, 종료일이 없는 진행 중인 책, 읽는 사람 구분, 날짜별 체크 독립성, 미래 날짜 체크 차단을 순수 함수로 구현하고 테스트한다.
2. 테이블과 접근 정책, 조회·저장·삭제, 실시간 구독을 구현한다. 같은 날짜에 책 여러 권이 겹쳐도 모두 조회되는지 확인한다.
3. 달력, 날짜 상세, 책·메모 입력 화면을 구현한다. 휴대폰 너비와 넓은 화면에서 여러 책 표시 및 긴 제목 처리를 확인한다.
4. 두 계정 또는 두 기기에서 책·메모·체크 변경이 공유되는지, 책 삭제 후에도 날짜 체크가 남는지 확인한다. `npm test`와 `npm run build`를 실행한다.

같은 날짜에 여러 책의 기간이 겹칠 수 있다. 독서 체크는 그중 어느 책을 읽었는지 나타내지 않는다.
